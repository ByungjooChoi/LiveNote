# LiveNote 기능 기획: Jamie · Granola · LiveNote 심층 비교 (2026-09-02)

목적: 두 경쟁 제품의 기능을 전수 조사하고 LiveNote(v1.3.0) 현재 상태와 대조해, 다음 개발 후보를 우선순위와 함께 정리한다. 코딩 지시가 아니라 기획 문서.

출처: Jamie 공식 changelog(2023-03 ~ 2026-08), Jamie vs Granola 비교(meetjamie.ai, zackproser.com), Granola 공식 블로그·Help Center(Chat, MCP, Pre-meeting briefs, Recipes), Upstarts 인터뷰(Recipes 런칭), 2026 리뷰들.

## 1. 제품 포지셔닝 한 줄 요약

|---|---|---|

| **LiveNote** | "실시간 + 로컬". 회의 중 영어 전사와 한국어 번역을 실시간으로 보며, 오디오는 Mac 밖으로 안 나가도 됨 | 실시간 번역, 로컬 STT + 2-pass 정제, Zoom 뮤트 동기화(에코 방어), 무료·개인 소유 md 파일 |

## 3. 갭 분석: LiveNote에 없는 것 중 가치 있는 것

Philip의 실제 사용 패턴(주 다수의 1:1과 고객 콜, 금요일 주간보고, Claude 헤비 유저, 한국어 번역 필요)을 기준으로 가중치를 매겼다.

### A. 화자 기억 (Speaker Memory) — Jamie의 간판, 우리의 최대 약점
- 현재: Zoom AX 타일에만 의존. Teams·Meet·대면·Zoom 신호 부재 시 "Speaker 1".
- 제안: LS-EEND가 이미 청크별 화자 임베딩을 내놓는다(FluidAudio `DiarizationResult` per-chunk embeddings). 이름이 확정된 화자(Zoom 태그·캘린더·사용자 지정)의 임베딩을 성문 DB로 저장하고, 다음 회의에서 임베딩 코사인 매칭으로 자동 명명. Zoom 신호가 있을 때 자동으로 학습되므로 라벨링 비용 0.
- 효과: 플랫폼 무관 화자명 + 현재 Zoom 취약점 이중화. 
- 난이도: 중상 (임베딩 저장 포맷, 임계값 튜닝, 동일인 다중 성문 병합).

### B. 사전 브리핑 (Pre-meeting Brief) — Granola의 2026 핵심 기능
- 현재: Coming up 카드에 제목·시간만.
- 제안: 회의 시작 10분 전(또는 아침 일괄) 참석자·제목으로 과거 회의를 찾아 "지난번 논의 요약 / 미완료 액션아이템 / 이번에 꺼낼 것 3가지"를 생성해 Coming up 카드에 펼침. 참석자 매칭은 캘린더 이메일 → 과거 회의 참석자/화자명.
- 효과: Craig 1:1, Intuit·MSG 고객 콜 준비 시간 단축. 아카이브를 실제로 쓰게 만드는 첫 기능.
- 난이도: 중 (검색 없이도 참석자·제목 매칭으로 후보 회의 선정 가능, LLM 1회 호출).

### C. Recipes — 저장된 프롬프트 워크플로
- 제안: 선택한 회의 집합(이번 주 / 특정 계정 / 최근 N개)에 프롬프트를 실행하는 버튼. 초기 레시피:
  - **Weekly Update 초안**: CLAUDE.md의 주간보고 작성 규칙(주어 생략, 판단·논리 흐름, SA 행위 중심, 배정 출처 미기재)을 시스템 프롬프트로 내장. 금요일 오후 클릭 한 번.
  - 후속 이메일 초안, 액션아이템 추출, 고객 콜 요약(영문), 한국어 요약.
  - 사용자 정의 레시피 추가 가능.
- 효과: 가장 즉각적인 시간 절약. Granola가 "아카이브를 유용하게 만든 첫 기능"이라 부른 그것.
- 난이도: 하~중 (프롬프트 라이브러리 + 멀티미팅 컨텍스트 조립, 기존 채팅 파이프라인 재사용).

### D. 액션아이템 구조화 + Tasks 뷰
- 제안: 요약의 "Next Steps"를 구조화 JSON(할 일·담당자·회의 출처)로도 저장하고, 사이드바에 Tasks 화면(미완료 목록, 체크, 출처 회의 링크). 사전 브리핑(B)이 이 데이터를 "미완료 항목"으로 재활용.
- 난이도: 중 (요약 프롬프트에 JSON 블록 추가 + 저장 + 뷰).

### E. 회의 중 Scratchpad + 요약 템플릿
- Scratchpad: 라이브 뷰 옆에 메모 패널. 저장 시 notes.md로 남기고, 옵션으로 요약 프롬프트에 "사용자 메모(우선 반영)"로 주입 (Granola의 cue 방식).
- 템플릿: 회의 유형별 섹션 구조(고객 콜 / 1:1 / 내부 싱크 / 인터뷰). 캘린더 제목·참석자로 자동 추천, 사후 재생성 가능.
- 난이도: 하~중.

### F. 전사 편집 + 찾아바꾸기 + 용어 학습
- 제안: 회의 상세에서 전사 행 인라인 편집, 이름/용어 찾아바꾸기(전체 회의 적용), 바꾼 단어를 Internal jargon에 자동 추가 제안. 향후 FluidAudio word boost로 디코더 레벨 반영.
- 난이도: 하~중.

### G. 소소하지만 체감 큰 것들
- 임시 회의 자동 제목(캘린더 없을 때 LLM이 제목 생성).
- "대면 회의" 시작 모드(마이크만, 다이어라이저 강제).
- 자동 시작 카운트다운(캘린더 회의 시작 시 5초 카운트다운 오버레이, 취소 가능).
- 녹음 안 켠 채 회의 앱에서 마이크 사용 중이면 알림(Jamie mic reminder).
- 회의 요약 클립보드 복사/공유용 md·HTML 내보내기.
- People/Accounts 뷰: 참석자·계정별 회의 타임라인 (검색 프로젝트의 메타데이터 기반이 됨).

### H. 의도적으로 안 넣는 것
- 봇/클라우드 스토리지/팀 공유/CRM 연동/모바일·Watch/전화: 개인용 Mac 앱 범위 밖. 필요하면 md 파일을 다른 도구(Claude, Obsidian)에서 읽는 편이 낫다.
- 동의 고지 자동화: 회사 정책 확인 후 결정.
- 스마트 검색(FTS5 + agentic): 2차 프로젝트로 보류 (기존 결정). 단 B·C·D는 검색 없이도 참석자·날짜 메타데이터만으로 동작하게 설계한다.

## 4. 우선순위 제안

| 순위 | 항목 | 가치 | 난이도 | 비고 |
|---|---|---|---|---|
| 1 | C. Recipes (Weekly Update 포함) | 매우 높음 | 하~중 | 기존 채팅 파이프라인 재사용, 즉시 효과 |
| 2 | B. 사전 브리핑 | 높음 | 중 | Coming up 카드 확장, 1:1·고객 콜 직결 |
| 3 | A. Speaker Memory | 높음 | 중상 | Zoom 외 플랫폼 커버 + 현재 취약점 이중화 |
| 4 | D. 액션아이템 구조화 + Tasks | 중 | 중 | B와 결합 시 가치 증가 |
| 5 | E. Scratchpad + 템플릿 | 중 | 하~중 | Granola 사용자 습관과 맞음 |
| 6 | F. 전사 편집·찾아바꾸기 | 중 | 하~중 | 고유명사 오류 정정 루프 |
| 7 | G. 소소한 것들 | 소 | 하 | 틈틈이 |

추천 순서: C → B → A. C는 하루, B는 이틀, A는 사흘 정도 규모. 세 개가 들어가면 Granola의 "아카이브 활용" 축과 Jamie의 "화자 자동화" 축을 모두 갖추면서, 실시간 번역·로컬 처리라는 LiveNote 고유 축은 그대로 유지된다.
